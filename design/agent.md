# 求职 Agent 增量设计

## 目标

在固定功能之上使用 Spring AI 完成模型驱动任务编排。默认只处理已有职位查询、匹配分析、材料生成和离线导入说明，不把 BOSS 采集改成无监督自动化，也不把模拟人工描述成防封号方案。

## 页面结构

- 左侧主导航保留“求职 Agent”和 AI 标记，真实点击路径必须有浏览器回归。
- 主区域依次为：目标输入与离线示例、后台任务结果、可选人工确认卡、实际执行轨迹。
- 右侧为已有职位使用说明、隐私边界和默认离线提示。
- 桌面双栏，900px 以下单主栏，600px 以下侧栏卡片单列；沿用现有紫色、面板圆角和按钮体系。

## 交互契约

1. 配置模型时，开始任务 POST 只创建并返回 `RUNNING` 快照；模型和工具在有界后台执行器中运行。
2. 前端每约 1.2 秒 GET 当前 runId，单实例定时器防止重复轮询；`COMPLETED`、`FAILED`、`CANCELLED` 等终态停止并刷新职位统计。
3. 轮询只读取本机任务记录，不刷新 BOSS；网络失败保留任务并自动重试，404 清理失效指针。
4. 无密钥本地任务立即完成，不进入无意义的后台等待。
5. 运行中不显示伪取消；只有 `WAITING_USER_ACTION` 且带确认单时显示确认/拒绝和取消。
6. 新对话清理定时器和当前指针，不删除数据库历史，也不谎称已中断正在执行的模型 HTTP 请求。
7. 执行轨迹只展示后端持久化步骤；localStorage 仅保存 runId 与 conversationId，不保存密钥、档案、工具结果或 Cookie。

## 后端边界

- `ChatClient` 负责规划与工具调用，`MessageChatMemoryAdvisor` 负责窗口记忆。
- `agentRunExecutor` 核心 2、最大 4、队列 32；提交拒绝和执行异常必须落库为 `FAILED`，不能永久 RUNNING。
- 默认只注册 6 个职位/档案/投递工具；`BOSS_BROWSER_ENABLED=true` 时才增加 2 个 BOSS 工具。
- BOSS 当前页采集不暴露为 `@Tool`，只能经确认单和 `AgentRunController.confirm()` 确定性执行。
- 确认单绑定 runId、action、过期时间和一次性状态；模型回答不能充当确认凭证。
- 页面动态文本先转义；静态 CSS/JS 使用版本参数，避免新 HTML 配旧脚本。
