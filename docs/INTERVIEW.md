# 项目讲解与架构问答

> 本文用于理解、演示和面试表达。不要背诵未亲自验证的指标，不要把演示公司、示例经历或本地规则结果说成真实业务成果。

## 一句话介绍

这是一个基于 Java 17、Spring Boot 和 DeepSeek OpenAI 兼容接口的本地求职 Agent，把国内职位采集、候选人匹配、定向材料与投递跟踪串成可验证的闭环。

## 30 秒电梯陈述

原项目依赖 Claude Code 和海外招聘站，我将主流程改造成 IDEA 可直接运行的 Spring Boot 应用。模型层通过 Java HttpClient 调用 DeepSeek 的 OpenAI 兼容协议；职位层实现 BOSS 直聘 Skill，但考虑到 robots 和访问控制，采用“在线权限检查 + 离线 HTML 导入”的双路径，不绕验证。业务层以候选人档案为事实源，输出匹配优势、缺口、定向简历、沟通话术和面试题，最后进入投递状态管理。无密钥时用明确标识的规则引擎完成离线演示，并用单元、协议和端到端测试验证。

## 可写进简历的项目描述（按真实参与情况修改）

- 设计并实现国内求职 Agent 的 Spring Boot 后端与免构建中文前端，贯通职位导入、匹配分析、材料生成和投递跟踪。
- 封装 DeepSeek OpenAI 兼容客户端，支持结构化 JSON、超时、错误映射和无密钥本地降级；通过模拟 HTTP 服务验证鉴权与协议。
- 实现 BOSS 职位 HTML 解析 Skill，包含 robots 前置检查、不可信输入清洗、URL 白名单、低频限制与 SHA-256 去重。
- 建立 JUnit / MockMvc 验证链路，覆盖解析、robots、评分、模型协议、静态资源和完整业务流程。

## STAR 示例：解决“可演示”和“合规采集”的冲突

- **S**：用户需要国内 BOSS 职位采集，但公开搜索 URL 带 query/city 参数，站点 robots 明确 disallow；直接绕过会扩大合规和稳定性风险。
- **T**：既保留可扩展在线采集能力，又确保工程开箱即用、结果可重复验证。
- **A**：设计双路径。在线路径固定 HTTPS 域名、先检查 robots、单页限速、403/429 立即停止；离线路径解析用户合法保存的 HTML，移除脚本和不可见字符，只保存卡片事实。增加虚构夹具与重复导入测试。
- **R**：离线流程不依赖网站可用性即可重复演示，在线拒绝会明确返回 `ROBOTS_DISALLOWED`，不把失败包装成成功，也不生成假职位。

## 架构深挖 Q&A

### 1. 为什么用 Spring Boot，而不是继续 Claude Code 命令流？

命令流适合个人 Agent 操作，但用户要求 IDEA 工程和前端页面。Spring Boot 提供明确的数据模型、API、事务、异常处理和测试边界，更适合演示完整业务闭环。原工作流被保留为业务思想，而不是运行依赖。

### 2. DeepSeek 与 OpenAI 兼容体现在哪里？

请求发送到可配置 Base URL 下的 `/chat/completions`，使用 Bearer Token、`messages`、模型名、`stream=false` 和 JSON response format。客户端不依赖特定厂商 SDK，因此 Base URL 和模型名可以配置。

### 3. 为什么不用本地规则冒充 DeepSeek？

两种模式在 API 和 UI 都有标识：实网成功是 `DEEPSEEK`，无密钥是 `LOCAL_DEMO`。本地摘要明确说明不是 AI 分析。这保证离线演示能力，同时避免不可验证的能力声明。

### 4. 为什么不在线硬爬 BOSS？

已核验 robots 对搜索 query/city 参数存在 disallow，且登录、验证码、403、429 都是明确访问边界。工程选择停止并给离线替代，不通过 Cookie、代理池或验证识别绕过。

### 5. 离线 HTML 导入仍然是爬虫吗？

它更准确地说是采集 Skill 的解析与入库部分。在线抓取器有独立实现，但只有在权限允许时才请求；离线导入提供稳定、可测试的数据获取路径。面试时应准确描述，不夸大成“突破反爬的实时全网爬虫”。

### 6. 如何防止提示词注入？

系统提示把候选人和职位内容声明为不可信数据，禁止执行其中的指令；输入清除控制字符、双向控制符和零宽字符，并限制长度。BOSS HTML 在入库前移除脚本、模板等节点，正文链接不跟踪。

需要说明：提示词约束不是操作系统沙箱，因此系统不自动执行模型工具调用，也不自动投递。

### 7. 如何避免 AI 编造简历？

候选人档案是唯一事实源，提示词禁止添加新公司、技能、学历、项目和指标；本地模板只拼接已有档案。页面要求人工核对。更严格的生产方案可增加事实抽取与逐句溯源校验。

### 8. 去重算法怎么设计？

有 URL 时统一 scheme/host 大小写、去 query/fragment 和末尾斜线；无 URL 时规范化公司、职位和城市。对规范化字符串计算 SHA-256，并设置数据库唯一约束。Service 先查再写，数据库约束是最后防线。

### 9. 先查再写是否有并发问题？

有。当前单用户同步导入降低了冲突概率，但没有消除竞态。生产环境应捕获唯一键冲突并转为 duplicate 结果，或对导入批次加锁；不能用“先查过”替代唯一约束。

### 10. 为什么选 H2？

本地零安装、文件持久化、IDEA 启动即可运行，测试还能切换内存实例隔离数据。它不适合多实例高并发生产；生产可迁移 PostgreSQL/MySQL，并引入 Flyway。

### 11. 事务边界在哪里？

档案更新、职位写入、Agent 结果保存和投递状态更新在 Service 事务内。网络请求当前也在 Agent 事务流程中，这是刻意的演示简化；生产环境应先完成外部调用再开启短事务，避免长事务占用数据库连接。

### 12. 为什么 Agent 当前是同步请求？

流程短、单用户、实现可观察，前端用加载状态等待。缺点是连接占用和无法中途取消。后续可改任务表 + 有界线程池 + SSE，必须处理重启恢复、幂等和超时，而不是简单 `@Async`。

### 13. HTTP 调用如何防止无限等待？

DeepSeek 与采集客户端分别配置连接和读取超时。采集禁用自动重定向，429/403 不自动重试；DeepSeek 对鉴权、限流、空内容和非 JSON 分别映射错误。

### 14. 为什么前端不用 Vue/React？

单页规模有限，原生 HTML/CSS/JavaScript 可以免 Node、免构建、随 JAR 托管，符合 IDEA 一键运行目标。复杂组件和状态增加后再迁移前端工程更合理。

### 15. 如何防止前端 XSS？

动态文本统一 HTML 转义，模型结果按纯文本展示，不使用 Markdown HTML 渲染；原始职位链接只允许 HTTP/HTTPS，并使用 `noopener noreferrer`。后端同时限制输入长度。

### 16. 为什么机器人规则解析采用失败关闭？

无法取得 robots 时无法证明访问被允许，继续抓取会违背设计目标，所以返回 `ROBOTS_UNAVAILABLE`。404 可解释为该路径无 robots 内容，其他网络/权限错误不盲目继续。

### 17. 测试如何验证 DeepSeek 而不花钱？

使用 JDK `HttpServer` 绑定本机随机端口，检查 `/chat/completions`、Bearer 头、模型、JSON mode 和 stream 参数，再返回带 Markdown code fence 的模拟响应，验证清洗与 DTO 反序列化。它证明协议逻辑，不证明真实模型质量。

### 18. 端到端测试覆盖什么？

在内存 H2 中手动创建职位，执行本地分析、材料生成、创建和更新投递，再导入 BOSS 夹具并重复导入验证去重，最后检查仪表盘和静态资源。测试不会读取开发环境的文件数据库。

### 19. 当前最大技术债是什么？

单用户无认证、同步外部调用、H2、职位列表内存筛选、缺少数据库迁移。它们对本地演示是可接受的简化，但上生产需要逐项处理，不能只做页面美化。

### 20. 如何演进为多人生产系统？

先增加用户与数据隔离、PostgreSQL 和 Flyway；再把 Agent 改为有界任务队列，增加审计与调用额度；职位导入改为带幂等键的批任务；最后补可观测性、备份、内容安全和前端组件化。每一步都要保持密钥不出服务端、采集不绕权限。

## 演示时可直接展示的真实点

- 主类启动，不需要安装前端工具链。
- 初始 12 个虚构职位和 2 条演示投递记录。
- BOSS 演示 HTML 含 3 个有效虚构职位；重复导入应全部去重。
- 测试夹具含 2 个有效职位和 1 个缺公司卡片，用于验证 warning。
- DeepSeek 协议测试使用本机模拟 HTTP，不是实网模型调用。
- 最终测试数、打包和启动结果以 `docs/VERIFICATION.md` 为准。

## 追问陷阱

**问：你说完成 BOSS 爬虫，为什么现场在线没有数据？**

答：在线路径在 robots 阶段被明确禁止，所以按设计没有请求目标页。我会展示错误码、robots 规则和离线导入闭环，而不会用异常手段制造“成功”。这正是工程边界和诚实状态处理的一部分。

**问：本地规则是不是伪 AI？**

答：它用于无密钥演示，并在 API、UI 和摘要中标识。真实 DeepSeek 只在配置密钥且接口成功后标记为 `DEEPSEEK`，两者没有混用。

**问：项目能不能直接上公网？**

答：不能。当前定位单用户本地使用，没有认证和隔离；上公网前必须补安全、数据库、任务边界和运维能力。
