# BOSS 直聘两步采集使用说明

适用版本：2026-11-08 浏览器协同修复版。新版页面只有“输入岗位，打开 BOSS”和“看到职位后，一键采集”两张步骤卡片；如果仍看到“解析意图 → 打开浏览器 → 勾选确认”的旧三步页面，请先按本文第 4 节更新工程。

## 1. 开始前准备

- 在 IDEA 中以 JDK 17 启动 `JobSearchApplication`，访问 <http://localhost:8080>。
- 本机安装 Chrome 或 Edge；首次使用保持默认“有头模式”。
- DeepSeek 只用于自然语言意图解析、匹配分析和材料生成，不是 BOSS 采集的必要条件。不配置密钥时仍可选择“按上方条件直接打开”，或手动录入、导入离线 HTML。
- 如需检查 DeepSeek，打开 <http://localhost:8080/api/ai/status>：`configured=true` 表示已读取环境变量；自然语言解析结果中的 `mode=DEEPSEEK` 才表示实际调用了模型，`LOCAL_RULES` 表示本地规则。页面和接口都不会返回密钥。

建议将 IDEA 运行配置的 Working directory 设为项目根目录。浏览器会话默认保存在 `./data/browser-profile`，工作目录不同会导致下次找不到原会话。

## 2. 两步采集

### 第一步：输入岗位，打开 BOSS

1. 进入“BOSS 职位采集 → 浏览器协同 + MCP”。
2. 二选一：
   - 输入“帮我搜集杭州 Java 后端岗位数据，最多 10 个”，点击 **解析并打开 BOSS**；或
   - 直接修改关键词、城市和条数，点击 **按上方条件直接打开**，不调用 DeepSeek。
3. 首次真正导航前，程序检查 robots.txt，只打开不带搜索参数的首页或 `/web/geek/job`。
4. 在弹出的真实浏览器中，由你手动扫码、完成站点验证、输入关键词与城市并搜索。

注意：应用中的“职位关键词”用于意图确认和结果核对，**不会自动填入 BOSS**。登录、验证、搜索和翻页始终由你操作，程序不构造搜索 URL。

### 第二步：看到职位后，一键采集

1. 如果搜索打开了新标签，先点击该标签，使职位列表成为当前活动标签。
2. 肉眼确认标签中已经稳定显示职位列表。可点击 **同步当前标签** 核对 URL；同步只读取状态，**不会刷新或重新导航 BOSS 网页**。
3. 点击 **确认当前页并采集**。这个按钮本身就是明确人工确认，不再需要额外勾选复选框。
4. 程序最多等待 8 秒让卡片出现，然后只读取当前活动 BOSS 标签中已渲染的卡片，单次最多 20 个，不自动翻页。
5. 结果区显示解析数、新增数、重复数，以及前 5 个“职位｜公司｜城市”预览。前往“职位库”可查看全部结果。

之后更换搜索条件或手动翻页时，不需要重新执行第一步：在浏览器中完成操作，激活结果标签，再执行第二步即可。

### 重复点击“打开”现在会怎样

- 当前已有 BOSS 标签：保留该页面，不重新导航，返回“已保留当前 BOSS 标签页，没有重新导航”。
- 当前是其他页面但浏览器里已有 BOSS 标签：切换程序读取目标到现有 BOSS 标签，不重新导航。
- 当前是站外页面且没有 BOSS 标签：新建 BOSS 标签，不覆盖站外页面。
- 切换有头/无头模式会重启浏览器上下文；登录和搜索完成后不要切换该选项。

## 3. 为什么旧版一直读基础页

旧实现有两个独立问题：

1. 每次点击“打开”都会再次 `navigate()`，可能覆盖你已登录或已搜索的页面。
2. 登录或搜索打开新标签后，程序仍可能读取最初的基础页，所以状态中的 URL 一直是 `/web/geek/job`，也读不到你看到的职位。

新版将打开操作改为幂等，并在状态同步和采集前重新识别活动标签，优先选择可见的 BOSS 标签。同时增加 `/job_detail/` 详情链接兜底识别和新布局字段选择器。页面持续刷新属于站点行为时，程序不会通过 stealth、验证码绕过或内部 API 对抗，应使用离线 HTML 备用路径。

## 4. 从旧 IDEA 工程升级

1. 在 IDEA 停止旧应用，并在旧页面点击“关闭会话”或关闭由应用打开的受控浏览器，避免两个进程同时占用同一会话目录。
2. 建议把新 ZIP 解压到一个新目录，不要直接覆盖仍有修改的旧工程。
3. 如需保留原职位、投递记录和登录会话，在应用完全停止后，将原工程根目录的 `data/` 复制到新工程根目录。不需要旧数据时可不复制。
4. 用 IDEA 打开新目录的 `pom.xml`，确认 JDK 17，重新加载 Maven，并检查原 DeepSeek 环境变量仍在运行配置中。
5. 运行 `JobSearchApplication`，浏览器打开 <http://localhost:8080> 后按 **Ctrl+F5** 强制刷新前端缓存。
6. 确认页面显示“两步完成”，再按第 2 节操作。

直接运行 JAR 时使用：

```bash
java -Dfile.encoding=UTF-8 -jar target/ai-job-search-cn.jar
```

## 5. 故障排查

| 现象 / 错误码 | 原因判断 | 处理方法 |
|---|---|---|
| 页面仍显示旧三步和确认复选框 | 运行的还是旧类或旧前端缓存 | 停止旧应用，使用新包重新构建启动，再按 Ctrl+F5；不要只替换 JAR 而继续运行旧 IDEA 进程 |
| 点击打开后 BOSS 反复回到基础页 | 旧版会重复导航；新版已有 BOSS 页时不会 | 核对是否出现“已保留当前 BOSS 标签页，没有重新导航”；更新后仍不要连续点击打开 |
| BOSS 自身一直刷新 | 可能是站点导航、登录状态或安全策略，应用状态同步不会刷新网页 | 停止重复操作，等待页面稳定；不要绕过验证。持续发生时改用普通浏览器保存 HTML 后离线导入 |
| 已搜索，但状态 URL 仍是 `/web/geek/job` | 当前激活的仍可能是基础标签 | 点击肉眼可见职位列表的搜索标签，再点“同步当前标签”；随后采集 |
| `NO_JOB_CARDS` | 当前活动标签没有可识别卡片，或仍停留在首页、登录页、空白基础页 | 确认结果列表真实可见并激活该标签；等待加载后重试。仍失败时用离线 HTML，说明线上 DOM 可能已变化 |
| `NO_VALID_JOBS` | 找到了容器，但缺少职位名或公司等必填字段 | 核对当前页确为职位列表；用离线 HTML 验证并保留一份脱敏样例供选择器维护，不用假数据补齐 |
| `PAGE_NOT_READY` | 读取时标签正在导航或刷新 | 等列表稳定后再手动点击一次采集；程序不会无限自动重试。持续发生时使用离线 HTML |
| `MANUAL_ACTION_REQUIRED` | 当前页仍有登录或安全验证提示 | 由你在真实浏览器中手动完成，再重新确认；不要尝试自动识别验证码 |
| `BROWSER_NOT_RUNNING` / `BROWSER_PAGE_CLOSED` | 浏览器未启动或标签已关闭 | 回到第一步打开 BOSS，然后手动搜索 |
| 登录状态丢失 | 工作目录或会话目录改变、会话被清理，或站点会话失效 | 固定 IDEA Working directory，保留 `data/browser-profile`；不要两个应用/MCP 进程同时占用该目录；失效时重新人工扫码 |
| 采集成功但职位库“没有新增” | 可能全部为重复职位 | 查看结果中的 `imported` 和 `duplicates`；重复数据不会再次插入，可按 `source=BOSS` 或关键词筛选已有职位 |
| 城市与预期不一致 | 卡片区域文本优先，表单城市只是缺少区域时的默认值 | 以预览和职位详情为准；必要时在职位库筛选，不能用默认城市覆盖卡片真实地点 |

## 6. 离线 HTML 备用路径

当线上页面持续刷新、结构变化或当前页读取失败时：

1. 在你正常使用的浏览器中打开并核对 BOSS 搜索结果，不使用本程序绕过登录或验证。
2. 通过浏览器“网页，仅 HTML”或“网页，全部”保存完整搜索结果页；也可以复制包含职位卡片的 HTML。
3. 进入应用“BOSS 职位采集 → 离线 HTML 导入”，选择文件或粘贴 HTML。
4. 点击“解析并导入职位”。程序在本机用 Jsoup 解析，不执行页面脚本，不请求详情页。
5. 点击“载入演示 HTML”可在不访问 BOSS 的情况下验证 3 个虚构职位的解析和去重流程。

离线 HTML 上限为 2,000,000 字符、单次最多 100 个有效职位；浏览器当前页单次最多 20 个。两者都会按规范化职位 URL 或“公司 + 职位 + 城市”去重。

## 7. MCP / Agent 调用

同一个 JAR 以 MCP STDIO 启动：

```bash
java -Dfile.encoding=UTF-8 -jar target/ai-job-search-cn.jar --mcp-stdio
```

提供 `boss_browser_start`、`boss_open_jobs_page`、`boss_browser_status`、`boss_collect_current_page`、`boss_browser_close` 5 个工具。Claude、Cursor 配置示例见 `mcp/`，完整契约见 [MCP_BROWSER.md](MCP_BROWSER.md)。

MCP 同样遵守两步流程：打开基础页后由用户手动登录和搜索；只有用户明确确认当前活动结果页后，才允许以 `userConfirmed:true` 调用采集。`importToApp` 默认 false，设为 true 时才通过本机 HTTP 导入另行启动的 Web 应用。
