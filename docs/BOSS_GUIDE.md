# 职位导入与可选 BOSS 功能使用说明

适用版本：2026-11-10 Agent 后台执行与默认离线修正版。

## 1. 先说明账号风险

本版不是“防封号方案”。默认配置为：

```text
BOSS_BROWSER_ENABLED=false
BOSS_ONLINE_ENABLED=false
```

因此正常启动后，应用、Agent 和 MCP 都不会自动启动 BOSS 浏览器、刷新页面、检查 BOSS robots.txt 或请求 BOSS 搜索页。推荐只使用**离线 HTML 导入**和**手动录入**。

即使手动开启浏览器协同，模拟人工点击、低频、只读当前页和 robots 检查也不能把封号风险降为零。本工程不会添加 stealth、代理池、验证码绕过、设备指纹伪装、内部 API 或自动翻页。

## 2. 推荐：离线 HTML 导入

这是步骤最少且不连接 BOSS 的导入方式：

1. 在你平时使用的浏览器中正常查看并核对职位列表，不使用本程序绕过登录或安全验证。
2. 通过浏览器“网页，仅 HTML”或“网页，全部”保存搜索结果页；也可以复制包含职位卡片的 HTML。
3. 打开应用左侧 **BOSS 职位采集**。本版默认已经选中 **离线 HTML 导入**。
4. 选择不超过 2 MB 的 `.html` 文件，或粘贴 HTML，点击 **解析并导入职位**。
5. 结果区显示解析、新增和重复数量；到“职位库”查看并继续匹配分析。

文件只在本机由 Jsoup 解析，不执行页面脚本、不读取 Cookie、不请求职位详情页。单次最多 100 个有效职位，按规范化职位 URL 或“公司 + 职位 + 城市”去重。

### 不访问网站的功能验证

1. 在“离线 HTML 导入”点击 **载入演示 HTML**。
2. 点击 **解析并导入职位**，应看到 3 个明确标识的虚构职位。
3. 再次导入同一内容，应全部计入重复，不重复插入。

这只能验证解析和入库，不代表 BOSS 当前线上 DOM 永远不变。

## 3. 手动录入

打开 **BOSS 职位采集 → 手动录入**，粘贴真实职位名称、公司、城市、薪资和描述后保存。该方式适合其他国内招聘平台、邮件或线下职位，不依赖 BOSS 页面结构。

## 4. Agent 最简单的使用方式

先完成离线导入或手动录入，再打开 **求职 Agent**：

```text
查询职位库里杭州的 Java 后端岗位，告诉我最匹配的 3 个及理由
```

```text
分析职位 ID 1 和我档案的匹配度
```

点击后立即创建后台任务，页面每约 1.2 秒读取本机任务状态。默认模式下 Agent 不获得 BOSS 浏览器工具，不会因为“搜集职位”而自动访问网站。

## 5. 可选功能：明确开启后才可用

只有你已经理解账号风险、确认有权进行相应操作，并确实需要原浏览器协同功能时，才在 IDEA Run Configuration 中自行添加：

```text
BOSS_BROWSER_ENABLED=true
```

需要原公开单页入口时另行添加：

```text
BOSS_ONLINE_ENABLED=true
```

两个开关相互独立，修改后必须重启。MCP 是独立 JVM，也必须为 MCP 进程单独设置相同环境变量。

### 浏览器协同开启后的两步

1. 在“浏览器协同 + MCP”输入岗位并打开无 query 的 BOSS 基础页。真正导航前检查 robots.txt；已有 BOSS 页面时不重复导航。
2. 你在真实浏览器中手动登录、完成验证、搜索并激活职位结果标签，再点击 **确认当前页并采集**。服务端只读取当前页一次，最多 20 个卡片，不自动翻页。

登录、搜索和翻页始终由你完成。持续刷新、401/403/429 或安全验证时应停止，不要通过重复点击或其他身份重试。

### 在线单页开启后的限制

在线入口仍会先检查 robots.txt；拒绝时不会请求目标页。编写原功能时核验的 BOSS robots 规则包含对 `?query=` 和 `?city=` 搜索地址的 Disallow，因此开启也不代表能够采集成功。不要把 `ROBOTS_DISALLOWED` 当作需要绕过的程序故障。

## 6. 从旧 IDEA 工程升级

1. 在 IDEA 停止旧应用；如果旧应用打开过受控浏览器，先正常关闭它和旧进程，避免两个进程同时占用会话目录。
2. 将新 ZIP 解压到新目录，不要覆盖仍在运行或有未保存修改的工程。
3. 如需保留职位和投递数据，在应用完全停止后备份并复制原 `data/`。浏览器会话不是必需迁移项。
4. 用 IDEA 打开新目录的 `pom.xml`，确认 JDK 17，重新加载 Maven，并重新检查 DeepSeek 环境变量。
5. 运行 `cn.jobsearch.JobSearchApplication`，访问 <http://localhost:8080> 后按 **Ctrl+F5**。
6. 核对页面：左侧 Agent 可点击；采集页默认是“离线 HTML 导入”；在线和浏览器页均标注“默认关闭”。

本版 CSS 和 JS 地址已增加版本参数，避免新 HTML 继续加载旧脚本。不要只替换 JAR 而让旧 IDEA 进程继续运行。

## 7. 常见现象与处理

| 现象 / 错误码 | 当前含义 | 处理方法 |
|---|---|---|
| `BOSS_BROWSER_DISABLED` | 浏览器自动操作默认关闭，未启动浏览器或访问网站 | 使用离线导入；确有需要时显式开启并重启 |
| `BOSS_ONLINE_DISABLED` | 在线搜索默认关闭，robots 和网络请求均未执行 | 使用离线导入；确有需要时显式开启并重启 |
| 浏览器状态显示“默认离线安全模式” | 正常的默认状态，不是启动失败 | 无需处理 |
| Agent 一直显示旧“同步请求”文案 | 旧进程或旧静态资源 | 停止旧实例，使用新工程重启并 Ctrl+F5 |
| Agent 显示“执行中” | 模型正在后台执行，POST 已返回 | 等待自动更新，可先看其他页面，不要重复提交 |
| `AGENT_STILL_RUNNING` | 后台模型/工具尚未结束，不能假装已经取消 | 等待终态；等待人工确认时仍可拒绝/取消 |
| `ROBOTS_DISALLOWED` | 仅会在主动开启在线功能后出现，目标搜索页未请求 | 停止在线访问，改用离线 HTML |
| `NO_JOB_CARDS` / `NO_VALID_JOBS` | 仅开启浏览器功能后，当前标签没有可解析职位 | 核对真实列表；持续失败时保存 HTML 离线导入 |
| `PAGE_NOT_READY` / 页面持续刷新 | 站点页面不稳定或正在风控 | 停止自动操作，不绕过；改用离线导入 |
| 导入后新增为 0、重复增加 | 相同职位已存在 | 在职位库按公司、职位或来源筛选已有数据 |

## 8. MCP 默认行为

同一个 JAR 仍支持 `--mcp-stdio` 和 5 个浏览器工具 Schema，但 start/open/collect 与 Web 共用同一个默认禁用边界：

- `boss_browser_start`、`boss_open_jobs_page`、`boss_collect_current_page` 默认返回 `BOSS_BROWSER_DISABLED`，不会启动浏览器。
- `boss_browser_status` 默认返回停止状态和离线说明。
- `boss_browser_close` 保留用于清理旧会话。
- 离线 `/api/crawler/boss/import` 不受开关影响。
